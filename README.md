# cheburcheck — пакетная проверка блокировок через cheburcheck.ru

Скрипт для массовой проверки списка IP-адресов, доменов, CIDR-подсетей и
автономных систем (ASN) на предмет блокировки в России через открытый API
сервиса [cheburcheck.ru](https://cheburcheck.ru/).

## Возможности

- Проверка **IPv4-адресов, доменов, подсетей (CIDR) и ASN** вперемешку из одного файла
- **Параллельные запросы** с ограничением количества одновременных соединений
- **Ретраи** с возрастающей паузой при ошибках сервера (429/5xx) и обрывах сети
- **Верификация** — повторные опросы того же адреса: при расхождении результатов
  адрес помечается `UNSTABLE`, а не угадывается
- **Динамическая проверка зондами ТСПУ** (по умолчанию ВКЛ) — как на сайте: сеть
  сканеров изнутри России реально тестирует доступность адреса (TCP/DPI) и выносит
  вердикт `tspu_block` / `sni_block` / `dns_spoofing` — информации, которой нет в списках
- **Бинарный результат** — вердикт выносят зонды: `BLOCKED` или `CLEAN`;
  если зонды не ответили (лимит/`429` сервиса) — ставится `UNKNOWN`
  (никогда не маскируется под `CLEAN`/`BLOCKED`), адрес — в `report/unknown.txt`
  на перепрогон
  (без «неопределённых» статусов); зонды выполняются строго ПОСЛЕДОВАТЕЛЬНО,
  чтобы не упираться в лимиты сервиса
- **Свежесть базы** — показывается время последнего обновления списков cheburcheck;
  предупреждение, если база старше суток
- **Дедупликация** адресов, поддержка комментариев (`#`) и пустых строк
- Формирование отчётов: TSV, CSV, чистые списки заблокированных/чистых/ошибок/нестабильных
- Цветной вывод в терминале, назначение кода выхода для CI
- Автоматически определяет источник распознавания адреса в ответе:
  «IPv4-адрес», «IPv4-подсеть», «Домен», «Автономная система»
- Возможность повторной перепроверки только ошибочных адресов

## Требования

- `bash` 4+
- `curl`
- `jq` **или** `python3` (для разбора JSON)

## Установка

```bash
install -m 755 check-ips.sh /usr/local/bin/check-ips
```

## Использование

```bash
./check-ips.sh -f ips.txt                        # проверить список из файла (с зондами ТСПУ — по умолчанию)
./check-ips.sh -f ips.txt -j 5 -r 3 -o report    # 5 потоков, 3 повтора, отчёт в report/
./check-ips.sh -f ips.txt --no-probe             # только списки, БЕЗ зондов (быстро)
cat ips.txt | ./check-ips.sh -                   # список из stdin
./check-ips.sh -f errors.txt                     # перепроверить только ошибки
./check-ips.sh -h                                # справка
```

### Формат входного файла

По одному адресу на строку: IP, домен, подсеть `a.b.c.d/len` или `AS<number>`.
Строки `# ...` — комментарии, пустые строки игнорируются, дубли убираются.

```
<IP-адрес>
<домен>            # комментарий: любой текст после # игнорируется
<подсеть CIDR>
AS<номер>
example.com
```

### Опции

| Опция | Назначение | По умолчанию |
|-------|-----------|--------------|
| `-f FILE` | файл со списком (или `-` = stdin) | — |
| `-o DIR`  | каталог отчёта | `.` |
| `-j N`    | параллельных проверок (1–8) | 3 |
| `-r N`    | повторов при ошибке/429 | 3 |
| `-t SEC`  | таймаут одного запроса | 15 |
| `-d SEC`  | пауза между запросами (анти-флуд) | 0.3 |
| `-v N`    | опросов на адрес (верификация) | 1 |
| `-p`      | динамическая проверка зондами ТСПУ: **включена по умолчанию** (см. раздел ниже) | вкл |
| `--no-probe` | отключить зонды — проверять только списки (быстро) | — |
| `--probe-timeout SEC` | сколько ждать ответы зондов (при тишине — reconnect) | 120 |
| `--probe-jobs N` | параллельность ЗОНДОВ для больших списков: `1` = последовательно (надёжно); `3-5` = быстрее, но чаще `no_response` → `UNKNOWN` | 1 |
| `-q`      | тихий режим (без построчного вывода) | — |
| `-h`      | справка | — |

### Прогресс

При большом списке (и включённых зондах) выводится «живой» счётчик:

- **этап 1 (списки)** — `[списки 42/256 · 01:23]` — обновляется раз в секунду;
- **этап 2 (зонды)** — `[зонды 100/256 · 04:01 · ETA 6м10с] <адрес>…` — с оценкой
  оставшегося времени по среднему темпу.

Вне терминала (лог/пайп) прогресс не печатается — только строки результатов и итог.

> Не поднимайте `-j` выше ~5 без необходимости: сервис чужой,
> агрессивный параллелизм может привести к ограничению доступа к API.

## Динамическая проверка зондами ТСПУ (`-p`)

Списки (РКН/antifilter/CDN) — это «бумажные» данные: адрес может быть в списке,
но реально доступен, и наоборот. Чтобы узнать, как адрес **реально** ведёт себя
из России, сервис запускает динамическую проверку: сеть зондов-сканеров изнутри РФ
делает TCP-подключения/трассировку к адресу и выносит вердикты:

- `tspu_block` — соединение режется на уровне ТСПУ (самый строгий признак)
- `sni_block` — блокировка по SNI
- `dns_spoofing` — подмена DNS-ответов
- `whitelist` — адрес в белом списке
- `ok` / `uncertain` — доступен / неопределённо

**Правило скрипта (бинарное):** зонды — основной сигнал, включены **по умолчанию**.
- если зонды дали **хотя бы один** блокирующий вердикт (`tspu_block`/`sni_block`/
  `dns_spoofing`) — адрес `BLOCKED`, даже когда в списках его нет; в `detail` —
  `probe:tspu_block;votes=8;pv=tspu_block=7;uncertain=1`
- если зонды подтвердили доступность (`ok`/`whitelist`) — `CLEAN` (если списки не
  говорят обратного); чистый вердикт **подтверждается вторым независимым сканом** —
  если он увидел блок, итог всё равно `BLOCKED` (вердикты зондов могут «флапать»
  между сканами)
- если зонды НЕ ответили (лимит/перегрузка `429`) — до 2 лёгких повторов со
  свежим `id`; если и так пусто — ставится `UNKNOWN` (адрес в `report/unknown.txt`
  на перепрогон), а вердикт списка сохраняется в `detail` как
  `probe:no_response;list=BLOCKED|CLEAN`. ПОД `CLEAN`/`BLOCKED` такие адреса
  не маскируются.

Порядок работы: **этап 1** — списки РКН/CDN параллельно (`-j`) с живым счётчиком
прогресса; **этап 2** — зонды ТСПУ последовательно (или `--probe-jobs N`
параллельно). Отключить зонды полностью: `--no-probe`.

Предупреждения:
- зонды **медленно**: каждый адрес держит SSE-поток до `--probe-timeout`
  (по умолчанию 70 с) и нагружает сеть зондов сервиса — не гоняйте большие списки
  с `-j` больше 1–2, иначе зонды перестают успевать отвечать
- **большие списки**: сначала прогон по спискам (`--no-probe`), затем выборочно
  подозрительные адреса с зондами
- работает для одиночных IP и доменов; для CIDR/ASN сервис зондов не запускается

## Ключевые проблемы и как скрипт их решает

**Почему результат может «плавать»:** cheburcheck проверяет по снапшотам
списков (РКН/antifilter/CDN-диапазоны), которые обновляются несколько раз в сутки.
Одноразовый опрос — это снимок на момент запроса: тот же адрес утром может быть
`BLOCKED`, а через час уже `CLEAN` (список пополнили/почистили).

- Скрипт **показывает свежесть базы** (время `last_update` и возраст) при каждом запуске.
- С опцией **`-v 2+`** каждый адрес опрашивается несколько раз, и если ответы
  расходятся (был и `blocked=true`, и `blocked=false`), адрес помечается как
  **`UNSTABLE`** с явной статистикой опросов — вместо однозначного «да/нет».
  Нестабильные адреса следует перепроверить позже.
- В `results.tsv` у каждого адреса есть столбец detail, где указано число опросов
  и раскладка: `verify:P=2;B=1;C=1;E=0` (B=blocked, C=clean, E=ошибки опроса).

## Файлы отчёта

| Файл | Содержимое |
|------|-----------|
| `results.tsv` | все адреса + статус (BLOCKED/CLEAN/UNSTABLE/ERROR), ASN, организация, CDN-провайдеры, заблокированные подсети, тип и детали: статистика опросов (`verify:P=2;B=…`), вердикты зондов (`probe:tspu_block;votes=8;pV=…`) при `-p` |
| `results.csv` | то же в CSV (для Excel/Google Sheets) |
| `blocked.txt` | заблокированные адреса + нестабильные (требуют внимания) |
| `unstable.txt` | только нестабильные (версии ответов расходились между опросами) |
| `clean.txt`   | только чистые адреса |
| `errors.txt`  | адреса с ошибками проверки (передавайте этот файл обратно в `-f`) |

Пример `results.tsv` (максимальная длина строки, поля сокращены):

```
<IP-1>            BLOCKED  <ASN-1>    <организация>    <cdn>
<IP-2>            CLEAN    <ASN-2>    <организация>
<домен>           CLEAN    <ASN-3>    <организация>    Домен;whitelist
```

Реальные колонки: `target TAB status BLOCKED/CLEAN/ERROR TAB blocked TAB asn TAB org TAB cdn TAB blocked_subnets TAB detail`.

## Код выхода

- `0` — адресов со статусом BLOCKED/UNSTABLE/ERROR нет
- `1` — найдены заблокированные/нестабильные адреса либо есть ошибки проверки
- `2` — неправильные аргументы командной строки
- Код `1` при наличии блокировок позволяет строить простые CI-проверки:
  `./check-ips.sh -f ips.txt || echo "есть блокировки"`

## Как работает

1. Файл нормализуется (убираются комментарии, пробелы, дубли) 
2. Запрашивается `/api/v1/status` — показываются время обновления базы и её размер
   (предупреждение, если база старше суток)
3. Каждый адрес кодируется в URL и отправляется параллельно:
   `GET https://cheburcheck.ru/api/v1/check?target=<адрес>` с заголовком
   `Accept: application/json`
4. При `-v 2+` адрес опрашивается несколько раз (с паузой `-d`); результаты
   опросов агрегируются: все = BLOCKED → BLOCKED, все = CLEAN → CLEAN,
   смешанные → UNSTABLE
5. Ответ разбирается через `jq` (или `python3`), извлекаются поля
   `blocked`, `geo.asn`, `geo.organisation`, `cdn_providers`,
   `blocked_subnets`, `target_type`, `rkn_domain`, `whitelist`, а также `id`
6. При включённых зондах (по умолчанию) во **второй, последовательной фазе** по
   полученному `id` открывается поток `GET https://cheburcheck.ru/api/v1/probe/<id>`
   (SSE): собираются вердикты всех ответивших зондов:
   - любой блокирующий вердикт (tspu/sni/dns_spoofing) → `BLOCKED`
   - `ok`/`whitelist` → `CLEAN` (если списки не говорят обратного)
- зонды молчат (лимит/429) → до 2 лёгких повторов со свежим `id`; если и так
      пусто — статус `UNKNOWN` (в `detail` — `probe:no_response;list=…`), адрес в
      `report/unknown.txt` на перепрогон. ПОД `CLEAN` такие адреса не маскируются
7. HTTP-ошибки 500/502/503/429 и обрывы соединения повторяются с паузой
   `2*c, 4*c, ...` внутри каждого опроса
8. Результаты собираются в порядке входного списка и пишутся в отчёты

## Ограничения

- Проверка идёт по базам **antifilter**, **cdn-ip-ranges** и собственным
  белым спискам cheburcheck — это неофициальный источник, возможны
  расхождения с реальной доступностью у конкретного провайдера
- Официальная проверка по реестру РКН выполняется через
  [blocklist.rkn.gov.ru](https://blocklist.rkn.gov.ru/) (с капчей, API нет)
- Результаты носят информационный характер

## Источники данных cheburcheck.ru

- Роскомнадзор (реестр запрещённой информации)
- https://cdnn.info / 123jjck/cdn-ip-ranges — диапазоны CDN
- https://antifilter.download и https://antifilter.network — зеркала списков
- Собственные белые списки, собираемые проектом Cheburcheck Reporter
